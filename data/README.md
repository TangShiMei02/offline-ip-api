# 数据目录

这里存放 IP 归属地数据文件，**文件不随仓库分发**，需要自己下载：

```bash
bash ../scripts/update_db.sh
```

下载完成后本目录下应该有两个文件：

| 文件 | 用途 | 大小（2026-08 版） |
|---|---|---|
| `ip2region_v4.xdb` | IPv4 查询 | 约 10.6 MiB |
| `ip2region_v6.xdb` | IPv6 查询 | 约 35.6 MiB |

只保留其中一个也能跑：

- 只有 `ip2region_v4.xdb` → IPv4 正常，IPv6 查询返回「无效或未收录」
- 只有 `ip2region_v6.xdb` → IPv6 正常，IPv4 查询返回「无效或未收录」

数据文件是 xdb v3 格式，构建时间写在文件头里。服务把这个时间报在
`GET /health` 的 `data.ipv4.built_at` / `data.ipv6.built_at` 上，
**用它确认自己到底在用哪一版数据**。

## 内存与缓存

引擎有三种缓存策略，用 `IPAPI_CACHE` 选（默认 `vector`）：

| 值 | 行为 | 进程常驻内存 | 单线程端到端延迟 |
|---|---|---|---|
| `vector`（默认） | 512 KiB 向量索引常驻，其余按需读文件 | 约 17 MB | 约 0.5 ms |
| `buffer` | 整个文件读进进程堆 | 约 63 MB | 约 0.38 ms |
| `file` | 什么都不常驻，每次查询都读文件 | 约 16 MB | 约 0.5 ms（波动较大） |

> 上表是在 1 核 / 512 MB 的容器上实测的，延迟含 HTTP 开销（完整对照见根目录 README 第六节）。
> `buffer` 用**近 4 倍内存**换约 1.4 倍的单线程速度；`vector` 让内核用 page cache
> 缓存数据文件，**内存紧张时这部分可以回收**。**小内存机器建议保持默认。**

文件被替换（比如跑 `update_db.sh`）后，服务会按 mtime **自动热重载，不需要重启**。
**不要**用多进程 / 多 worker 启动服务，否则每个进程都会各加载一份。

## 旧版本的文件名

1.2.0 及更早用的是 ip2region 的 v1 格式，文件名是 `ip2region.db`（IPv4）
和 `ipv6wry.db`（IPv6，纯真库）。**这个格式的上游数据已经停止更新**，
1.3.0 起换成官方 xdb v3，旧文件可以删掉：

```bash
rm -f ip2region.db ipv6wry.db
```

数据来源与授权见项目根目录 README 的「数据来源与许可」一节。
